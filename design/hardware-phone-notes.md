# 실제 제품 · 앱 체험 구현

## 구현 결과

- 실제 제어 본체 사진을 메인에 크게 배치. 제공된 설치 사진 두 장과 전환·확대 가능.
- 앱 캡처를 참고한 휴대폰 프레임과 조작 가능한 목표 온도 UI. 16–36°C, 0.5°C 단위, 적용 동작 지원.
- 조작은 체험 상태만 변경하며 실제 기기에 요청하지 않음. 측정값을 목표 온도에 맞춰 인위적으로 바꾸지 않음.
- 9/14 05:20–05:55의 8개 기록을 전사해 시간 선택·재생·비교 그래프로 제공.
- 06:00의 빈 기록을 그대로 표시. 실제 앱 원본 2장을 모달로 확인 가능.

## 성능 표현의 근거

1. 사용자 제공 테스트 설명: 목표 26.5°C, 외부 10–20°C 변화, 약 ±0.2°C 편차. 제공된 테스트 사례로 표기했다.
2. 첨부 앱 기록: 내부 26.3–26.6°C, 외부 22.6–24.4°C. 1번과 다른 측정 구간임을 표시했다.
3. 설정 화면 원본에는 별도 시점의 오프라인/마지막 측정 상태가 포함돼 있다. 웹 체험의 현재 기기 연결 상태로 사용하지 않았고 원본 보기는 그대로 보존했다.

전사 데이터는 `src/app/_components/hiveRecord.ts`, 원본 사진과 캡처는 `public/images/product/`에 있다. 제공 자료 외에 독립적인 기기 시험을 실시하지 않았다.

## 검증

프로덕션 빌드·TypeScript·ESLint 통과. 로컬 Playwright/Chrome으로 온도 증감/상하한/적용, 측정값 불변, 원본 모달 닫기/Escape, 갤러리 전환, 기록 선택/재생, 실제 그래프를 검증했다. 320·390·768·1024·1440px에서 가로 넘침이 없었다. 모바일 터치·동작 줄이기도 확인했다. 브라우저 오류와 체험 API 요청은 0건이었다.

시각 검토에서 초기 휴대폰 높이 때문에 가려진 적용 버튼을 수정했고, 모바일 사진 디코딩과 애니메이션 완료 후 최종 화면을 다시 촬영했다. 본체 외형은 생성하거나 변경하지 않고 원본 사진을 사용했다. 제공된 앱의 색상·수치·슬라이더 범위·강조 버튼을 참고하되, 랜딩페이지 체험에 맞게 일부 화면을 간소화했다.

## 외부 플러그인 실행 상태

Higgsfield와 Figma는 플러그인 관리 조회에서 설치·활성 상태로 확인됐다. 요청된 Higgsfield, figma-use-motion 및 기반 스킬을 읽었다. 그러나 현재 작업의 사용 가능한 도구 목록에는 두 서비스의 생성/편집 도구가 없었다. 따라서 Higgsfield 영상 생성, Figma 파일 생성/저장, Figma Motion API 실행은 수행하지 못했다. 웹의 모션은 CSS와 React로 구현했다. 외부 서비스 결과물이나 Figma URL을 생성한 것으로 주장하지 않는다.

후속 제작 구성은 `higgsfield-figma-brief.md`에 정리했다. 사이트 배포는 하지 않았다.
